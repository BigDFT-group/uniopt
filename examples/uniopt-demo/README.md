# UniOpt demo

This executable demonstrates one schema driving parsing, validation, help,
Markdown, JSON, and Bash completion.

```bash
./examples/uniopt-demo/uniopt-demo --help
./examples/uniopt-demo/uniopt-demo --style formal --tag docs --tag demo Ada
./examples/uniopt-demo/uniopt-demo --quick Ada -- '' 'two words' '*'
```

Enable completion for the current shell:

```bash
source examples/uniopt-demo/completion/uniopt-demo.bash
./examples/uniopt-demo/uniopt-demo --style <TAB>
```

Completion is registered for the command name `uniopt-demo`. For the repository
path shown above, either add `examples/uniopt-demo` to `PATH` or register the
same function for that path:

```bash
complete -F _uniopt_uniopt_demo ./examples/uniopt-demo/uniopt-demo
```

The committed completion, Markdown, JSON, and help snapshots are generated by
`scripts/generate-docs` and checked by CI.

## Open the generated GUI

The same schema also drives the native-or-web line advisor:

```bash
./examples/uniopt-demo/uniopt-demo --gui
```

On a desktop, automatic selection tries Qt and then Tk. Without a usable native
display it prints a URL for the standard-library web frontend. The compatibility
launcher `./examples/uniopt-demo/gui` also accepts `--backend`, `--open`, and
`--port` for direct frontend testing.

Inside WISE or another container, `127.0.0.1` belongs to the container. Choose
a fixed port, leave `--open` off, and forward that port through the IDE:

```bash
UNIOPT_GUI_BACKEND=web UNIOPT_GUI_PORT=8765 \
  ./examples/uniopt-demo/uniopt-demo --gui
```

In WISE's **Ports** view, forward port `8765` and use **Open in Browser** on the
forwarded address. The form is also served at the forwarded address's `/`
path. The Run request uses a same-origin relative URL, so it continues to work
when WISE assigns a different host-side port. The `--open` option is intended
for a browser sharing the GUI process's network namespace.

The advisor shows the exact argument vector before execution. Its repeatable and
remainder editors preserve one row as one argument, including empty values and
embedded newlines. The runner invokes the fixed `uniopt-demo` executable with
an argv array and never uses a shell command string. For safety, this teaching
native frontend provides file and directory dialogs for path-typed values.

The labels, sections, ordering, and controls come from the `--ui-*` declarations
in [`schema.sh`](schema.sh). See the
[GUI design guide](../../docs/installation-and-gui.md) for their contract and
for the behavior a production adapter must implement.

## Install the command and completion

The example includes the same installation pattern an application can adopt:

```bash
PREFIX="$HOME/.local" ./examples/uniopt-demo/install
export PATH="$HOME/.local/bin:$PATH"
```

The installer places these files:

```text
~/.local/bin/uniopt-demo
~/.local/share/uniopt-demo/schema.sh
~/.local/share/uniopt-demo/lib/uniopt.sh
~/.local/share/bash-completion/completions/uniopt-demo
```

When a Bash completion loader is configured, start a new Bash and completion is
available automatically. Otherwise add this portable fallback to
`~/.bash_profile`:

```bash
source "$HOME/.local/share/bash-completion/completions/uniopt-demo"
```

Then use `uniopt-demo --style <TAB>`. Installation cannot modify the state of
an already-running shell, so either start a new shell or source the completion
file once in the current shell.
